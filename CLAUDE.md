## Current state: the farm plot
The world is the player's farm plot, built from the reference screenshots (camera facing north = -Z). There is a HUD with windows and a small single-player economy (below), saved to localStorage; no networking yet. The floating 3D cards over the coops are static; the FARM STAND card (`stand.js` `standCard`) is live (stand eggs, price per egg, customers a minute) and its green EGG PRICE + button buys the Shop's Egg Price upgrade on a click / tap (`hud.click` raycasts the sprite and checks the hit uv; hover shows a pointer cursor; on touch a quick tap on a touch zone is a world click via `input.js` `worldTap`). Old code from earlier games is in git `HEAD` (`git show HEAD:src/<file>`): check there before rewriting something generic (windows shell, HUD, net, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures, synthesised audio); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js`. The plot layout is `FARM` (every area as a `{ minX, maxX, minZ, maxZ }` rect: road, sidewalks, chicken yard + coops, farm stand plaza, field, truck bay, drop-off, racks, barn, seed market plaza, upgrade `pads`, the north end: dirt road, rail, crossing, ranch, oil barrels, train timing). Sound levels are `AUDIO`.
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked).
- **Analytics** (`src/analytics.js`, GameAnalytics npm SDK): off unless `VITE_GA_GAME_KEY` / `VITE_GA_SECRET_KEY` are set (deploy.yml sets them from the repo secrets `GA_GAME_KEY` / `GA_SECRET_KEY` for the prod build only). Sends Load:Done, tutorial progression per step, Build / Field / Vehicle / Hire milestones (value = play minutes), first Sell:Stand / Sell:Market a session, Level:Up, Prestige, Ad:Break, Net:Joined / Dropped / Offline and script errors; dimensions touch/desktop, guest/signedIn, graphics preset. Never send Bloxity ids or names. New milestones go through `analytics.design(id, value)`, never throwing.
- **Bloxity integrations** (all but Gems; docs.bloxity.io): `bloxity.js` init enables party play (`party.enable`, 4 = a town), declares the hosted leaderboards (`LEADERBOARDS`: level / earned / prestige / eggs, ids shared with the backend's `LB_BOARDS`; the SERVER reports the scores from each saved farm), registers `emotes` (portal emote wheel -> `onEmote`) and `play_with_friends` (after a join), wires ad breaks (`onAdBreak`: main.js stops the loop and mutes), declares ad screens (`gameplay` reported on first frame), and relays Bloxity chat (`onChat`, text via `chat.bubbleText`). `net.js` joins with the Bloxity game `token` (a deployed server verifies it, never a client id), tries the launch `?roomId=` (invites / Open Rooms) first, resolves a fresh endpoint per connect, calls `updateRoom` on join / leave and reconnects on an unexpected close. Join toasts: `playerInRoom` / `playerJoined` (remotePlayers.js).
- **Boosts are earned by inviting** (`GAME.boosts` `unlock`, `game.js` `invite` / `boostActive` / `setInvite`; `moneyBoost()` only counts active ones): the Money Boost once the player has sent an invite (a Bloxity friend from the list or the shared invite link), the Friends Boost once a friend they invited actually joined (server-credited, backend `invite.ts`). The server's `invite` message is the authority (`net.js`; guests: both locked); `invite` lives outside `state` (reset / prestige keep it) and is cached in localStorage `run-a-farm.invite.v1`. `hud/invite.js` `openInvite` (from the HUD boost icons, which show a padlock while locked, and the Shop's boost cards): boost status, COPY LINK (`bloxity.inviteLink`, tagged `ref` = our account; joiners send it as the join option `ref`) and the Bloxity friends list with INVITE (`bloxity.inviteFriend` -> `net.sendInvited`). Toasts on `friendJoined` / `invitedBy`.
- **Other players** (`src/remotePlayers.js`, `REMOTE` tunables): each roster player as their Bloxity look (`net.setLook` sends `{ equipped, proportions }` ids; receivers compose the skin with `getSkinTextureUrlFor`), the locomotion animator, their vehicle (`net.setRide` -> roster `ride` 'kind/seat'; pooled `farm/vehicles.js` models / horse), emotes (`avatar/emotes.js` `EmotePlayer`: catalogue clips as deltas over the bind pose captured by `captureBind`, stop on movement; roster `emote` + `emoteAt` server ms, `net.serverNow()`), chat bubbles (`bubble.js` `speechBubble`, also ours in main.js) and a name tag. Poses are mapped with `farm/remote.js` `mapPose` and drawn ~0.22 s behind through a snapshot buffer. Perf: nothing past `REMOTE.hide` m, no shadows / every-frame animation past `near`, tag and vehicle rig off past `far`, no animator work off-screen, one avatar build at a time, `net.roster()` entries reused (no per-frame garbage).

## Roadmap systems (`src/econ/`, added on top of `game.js`)
Each module hooks `game.mods` (price, lay, customers, grow, ranch, boost, drone, level, seedPack, deliver) and listens to game events; `econ/index.js` `tickEcon(dt, player)` runs them every frame after `game.tick` (main.js). Their state lives in `game.state` slices (`clock`, `proc`, `contracts`, `care`, `xp`, `ach`, `life`, `tutorial`, `fleet`, `managers`, `course`, `prestige`) so saving and resetting just work. Tunables are in `config.js` (the "Roadmap expansion" section: `Object.assign(FARM, …)` / `Object.assign(GAME, …)`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> clouds, lighting, the farm (`buildFarm`) + audio -> player body -> avatar (async, swaps in when ready) -> loop (physics, interpolate player, avatar animator, camera, clouds, farm update, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse / pointer lock into `inputState`; `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Sky dressing**: `world.js` `createWorld(scene)` adds the drifting clouds. The ground is `farm/terrain.js`.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` and `setMoods(sky)` are unused hooks. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom). `nightLevel()` gives the eased day/night blend.
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` merges a Group's static meshes to one mesh per material (draw-call saver; used through `farm/kit.js` `bakeInto`).
- Controls: WASD/arrows, Shift sprint, Space jump, mouse look (click grabs the cursor = pointer lock, Esc releases it, then Esc opens the portal menu), wheel zoom, V mode, N day/night, R respawn. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
